# habit-design

Turn a wish to start a habit into a cue (if-then plan) and a period, then wait for yes.

Allowed tools: listHabits, searchKnowledge, createHabit.

1. For a wish such as "I want to run", propose one habit with one cue anchored to something the person already does: "After my morning coffee, I will run." Treat an unconfirmed anchor as a proposal; ask one question if more context is needed. Use listHabits when needed to avoid duplicate names.
2. Propose one period: Daily habit or Weekly habit, tracked once or as a Many-times habit with a Habit goal. Use Bad if the person is cutting down. Weekly means Monday–Sunday. Keep the design to the cue and period.
3. Call searchKnowledge for "If-then plans". Quote evidence only from that returned section, including its limits and source. Make no research claim from memory or another section. If no section matches, say so without inventing evidence.
4. Present the cue and period, then wait for an explicit yes. Create nothing in the proposal reply. Only after yes, call createHabit for the agreed habit using its existing rules and defaults. Keep the cue in the proposal; createHabit has no cue field. Use the usual creation receipt and never claim a failed write succeeded.
